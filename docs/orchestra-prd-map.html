Orchestra, a conductor and its musicians inside Claude Code

A Claude Code plugin with a conductor agent and five musician subagents, plus a mod that records every file each musician reads and writes into a per-session ledger with SHA-256 versions. The mod holds any write that would overwrite another musician's newer work and asks you, and draws the ensemble on the surfaces a mod may draw.

What the user experiences

PRD §1.1

Install

claude plugin install orchestra@orchestra-cc from the public marketplace.

Start

claude --agent orchestra:conductor. The header shows the conductor.

Describe the task

The conductor writes .orchestra/score.md and starts independent parts in one message, so they run in parallel.

Watch

Band, status line and pane show who plays, each tool, measures, reads, writes, handoffs, stale reads and failures.

Decide conflicts

A write on a version the writer never saw is held, and you are asked in Claude Code's question dialog.

Read the coda

Written from the ledger at each conductor turn end: file, Coda tab and /orchestra coda.

System architecture

PRD §3

The conductor and musicians are ordinary Claude Code agents. Everything Orchestra observes comes through mod events, which carry each subagent's agentId; everything it shows is folded from one ledger file.

Ctrl/Cmd + wheel to zoom. Drag to pan when zoomed. Double-click to fit.

Why a mod

Only mod events attribute each tool call to a subagent, only a mod can hold a write and ask, and only a mod can draw a pane, band and status line.

Why not settings hooks

They can record events, but they cannot draw or ask. They remain a possible fallback where mods are disabled.

Privacy

No network calls. Stores prompts (≤500 chars), briefs (≤600), answers (≤1,200), paths and hashes. Never file contents. .orchestra/.gitignore is *.

Data model: observations in, derivations out

PRD §3.2 · Spec §4
Recorded eventWhen
part.assignedAn Agent call started a subagent; carries id, type, description, brief
tool.call / tool.resultAny loop runs a tool, and how it ended
artifact.readA Read succeeded; SHA-256 of the file then
write.attemptJust before Write, Edit, MultiEdit, NotebookEdit
artifact.writeThe write landed; new hash, lines added and removed
conflict.resolvedYour choice: overwrite or reread
part.done / part.failedThe subagent's turn ended
codaThe coda file was written

Version

Each distinct SHA-256 of a path, numbered from v0, the content first seen.

Conflict

The writer's last-seen version is not the current one, or it never saw the file and another musician wrote it.

Stale read

A musician produced work after reading a version someone later replaced. Clears when it re-reads.

Handoff

Musician B read a version musician A wrote. A second signal comes from conductor briefs that name a file another musician wrote.

Storage: the ledger is written in 500-event segments, and only segments with new events are rewritten, so a torn write can lose at most part of one segment. A live 559-event ledger was saved across two segments with no gaps.

Never colour alone

Every state pairs a glyph with a word: ♪ playing, ‖ waiting, ✓ done, ✕ failed. Alerts say “conflict”, “stale”, “failed”.

Text path

/orchestra coda prints the whole coda into the transcript. Band and status line are single lines in a fixed order.

No motion of its own

Orchestra animates nothing; the only animation is Claude Code's spinner.

Delivery order

PRD §3.6

Each step ships on its own. Every step below is built and was verified in real runs on 2026-10-05; see docs/verification.md.

Agents

Conductor and five musicians with roles, tool limits and per-agent model defaults.

Capture and ledger

Hashed reads and writes per musician; replay on reload.

Conflict guard

Hold, ask, deny with reason; headless send-back.

Band and status line

Instrument names, glyphs, measures and current tool.

Pane tabs

Ensemble, Score, Artifacts and Coda, by keyboard.

Toasts and Agent-row labels

All five toast kinds; labels on single Agent rows.

Segmented ledger

500 events per segment; replay on resume.

Show both versions

Drawn above the dialog, within its 12-row limit.

Publish to krzemienski/orchestra-cc

Public. Version 0.1.1 adds the never-read send-back and the code-review fixes.
